## 审计机制

### 触发条件（满足任一）
- 单次任务完成，输出前
- 多轮任务每 5 轮
- 用户显式要求审计

### 执行方式
由主代理内联执行，不启动子代理。主代理直接读取审计清单：
- `cat .claude/expandable/audit/rule-audit-checklist-short.md`

若需要快速比对高频失败模式，可同时参考：
- `.claude/expandable/audit/audit-failure-examples-min.md`

主代理基于当前会话上下文（无需二次摘要传递）对照清单逐项检查。

### 审计检查维度（主代理对照当前上下文自检）
- 已加载的规约文件列表
- 已加载的模板列表
- 任务类型
- 是否调用了工具（及数量）
- 是否使用了子代理/代理团队
- 是否为周期性任务
- 最近一轮输出的 token 量级（短/中/长）
- 最近一轮仅保留“新增变化”的摘要，禁止附完整历史、长日志或原始工具输出
- 是否存在长时间无结果的外部调用、阻塞子代理或非阻塞型 hook 错误噪音
- 是否有外部目标超出“轻量探测”预算却未先上报主代理或请求人工确认

### 审计输出格式（主代理直接输出）
```
审计结果: 通过 | 有问题
问题项: [未通过的检查项编号及一句话说明]
建议: [最关键的一条改进]
```

### 审计结果落盘（主代理执行）
- 触发审计后，主代理应将本次审计结果保存为 Markdown 文档。
- 建议路径：`.claude/audit-reports/<yyyy-mm-dd>-<task-or-session>-audit.md`
- 文档至少包含：任务摘要、审计输入摘要、审计结果、问题项、建议、生成时间。
- 默认可参考：`.claude/expandable/templates/audit-report-template.md`
- 若本轮无问题，也应写入文档，并标记“审计结果: 通过”。
- 保存完成后，主代理必须在回传中明确上报该 Markdown 文档路径，便于后续追溯。

### 审计后动作（主代理执行）
- 若审计结果为“通过”：直接继续当前流程，不额外展开审计说明
- 若审计结果为“有问题”：优先按“建议”修正当前轮的执行路径或输出，再决定是否继续
- 若问题项属于 L/T/Q/D：默认在主代理本地收敛，不新增子代理或模板
- 若问题项属于 S/A/C：优先压缩上下文、只保留新增变化，再重新组织输出
- 若发现阻塞子代理或慢速外部调用：优先停止等待、保留已完成结果，并改用轻量来源或串行分析补齐
- 若发现已越过范围预算却未升级：优先回退到已验证范围，并补一次主代理决策或用户确认
- 审计结果保存后，主代理对内至少补充一行：`审计报告位置: <markdown_path>`
- 除非用户显式要求查看审计细节，否则对外只反馈修正后的结果，不回灌完整审计过程

### 约束
- 审计由主代理内联执行，不启动子代理，不触发额外规约加载
- 审计结果不超过 5 行
- 若全部通过，只返回"审计结果: 通过"
- 审计发现的问题优先在当前轮闭环修正，避免把审计本身变成新的上下文膨胀来源
- 审计 Markdown 文档由主代理保存
