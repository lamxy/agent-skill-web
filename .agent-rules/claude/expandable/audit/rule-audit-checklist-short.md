# 规则审计检查清单（MVP 速查版）

## 规则加载
- [ ] L1: 是否先用最小规则？
- [ ] L2: 简单任务是否停在常驻层，未加载极简规约？
- [ ] L3: 是否只加载了最相关的一个极简规约？
- [ ] L4: 多场景命中时是否按优先级选择，而非全部加载？
- [ ] L5: 模板是否仅在需要稳定格式时才加载？

## 工具调用
- [ ] T1: 工具调用是否真的必要？
- [ ] T2: 工具输入是否足够聚焦？
- [ ] T3: 工具输出是否先筛选、去重、摘要？
- [ ] T4: 是否避免把原始长结果塞回主会话？

## 子代理
- [ ] S1: 子代理边界是否清晰？
- [ ] S2: 子代理输入是否最小？
- [ ] S3: 子代理输出是否短而结构化？
- [ ] S4: 主代理是否真的做了去重、合并、裁决？

## 代理团队
- [ ] A1: team leader 是否在做拆解、分配、汇总，而不是转发原话？
- [ ] A2: team agent 是否只拿到最小必要上下文？
- [ ] A3: team agent 输出是否只包含局部结果、证据、风险、下一步？
- [ ] A4: 团队对外输出是否先结论，再给共识、冲突、风险、下一步？
- [ ] A5: 长周期团队协作是否只汇报新增变化？

## 周期任务
- [ ] C1: 是否只汇报变化？
- [ ] C2: 是否把详细日志外置？
- [ ] C3: 主线是否保持状态摘要，而不是日志堆？
- [ ] C4: 是否只在关键状态变化时上报？

## 输出质量
- [ ] Q1: 是否先结论后解释？
- [ ] Q2: 是否高信息密度？
- [ ] Q3: 是否少重复？
- [ ] Q4: 是否结构清晰？

## 规约披露
- [ ] D1: 是否默认不提示规约？
- [ ] D2: 若提示，是否真的有帮助？
- [ ] D3: 是否一轮最多一次？
