# 弱网与低质量代理偏好极简规约

适用于通过代理链路访问外部模型、GitHub、网页或插件服务时，出现高延迟、Fast mode 不可用、首字节缓慢、子代理长时间无结果等情况。

规则：
- 先把任务降级为“最小可完成路径”，优先完成，再考虑完整性。
- 外部仓库分析优先读取 README、目录或单一关键文件；默认不做全仓爬取。
- 若目标仓库或网页明显超出轻量预算，先回报“范围过大”，再由主代理决定是否缩小目标或请求人工确认。
- 默认减少并行外部请求；多个仓库或网页优先串行轻量探测，只有首个目标证明成本可控后再扩大。
- 子代理默认一次只处理一个外部目标，且结果必须保持短格式；弱网下避免同时派发多个重型分析子代理。
- 若某个子代理长时间无结果，允许按 `blocked` 处理，并基于已完成结果继续推进主流程。
- 把 PostToolUse、插件写日志失败、相关目录缺失等现象优先视为噪音，先判断它是否真的阻断主任务。若 hook 或插件只产生日志噪音，避免为排查噪音而重复原始外部请求。
- 给用户的结论应优先说明已验证部分、未验证边界与建议下一步，不为追求完备而无限等待。

避免：
- 因非阻塞型 hook 错误而误判主任务失败
- 直接把阻塞中的子代理当成必须等待的前提条件
