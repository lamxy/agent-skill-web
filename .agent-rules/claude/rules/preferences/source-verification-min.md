# 信息源验证极简规约

适用于任何涉及外部信息源的工具调用：GitHub 仓库、网页、文档、API 结果等。
本规约不决定是否调用工具，只约束调用后的取证方式与结论边界。
通常与 `tool-call-rule-min.md` 联用。

## 核心原则

**摘要不是事实，原始内容才是。**


## 工具优先级

读取外部信息时，按以下优先级选择工具：

  
| 信息源 | 优先工具 | 禁止替代 |
|--------|---------|---------|
| GitHub 文件/README | `get_file_contents`（GitHub MCP） | WebFetch 摘要 |
| GitHub 仓库结构 | `get_file_contents` 列目录 | 凭空推断 |
| 网页原文 | WebFetch 原始内容 | 搜索摘要片段 |
| 用户指定工具 | 严格使用指定工具 | 任何替代 |


## 验证规则

- 描述任何项目的性质、功能、架构前，必须先读原始文件
- 摘要只能作为线索，不能直接作为最终事实或结论
- WebFetch 返回内容结构过于"整洁"时，视为摘要风险信号，用原始工具验证
- 未被原始来源证实的信息，必须标记为"未验证"，不得补全、推断或下最终结论
- 工具返回为空或不足时，明确说明"未找到"，不用已知知识填充


## 短示例

### 仓库分析
反例：用 WebFetch 摘要或搜索总结直接下结论，未回到 README/目录核验。
正例：判断前先读原始文件；原始文件未说明的信息输出"未验证"。

### 网页分析
反例：读摘要后把整理结果当原文明确声明。
正例：优先读网页原文；返回内容过于整洁时视为摘要风险信号，再做核验。

### 用户指定工具
反例：用户指定工具后仍改用其他工具或来源。
正例：严格按指定工具取证；结果不足则说明证据不足，不自行替换。


## 避免

- 用 WebFetch 摘要替代 GitHub 原始文件读取
- 因工具结果模糊而补全不存在的类名、功能、架构
- 对项目性质（框架 vs 工具集 vs 提示词库）在读取前做假设
- 用户明确指定工具后仍使用其他工具
