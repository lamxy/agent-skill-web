# 指令编写风格约束

适用于编写或修改任何用户指令、提示词、规则、规约、行为准则文件时。

## 核心区分

| 类型 | 定义 | 位置 |
|------|------|------|
| **行为指令** | 模型必须执行或禁止的操作，主语是模型 | 正文 |
| **维护性说明** | 面向人类维护者的操作指引（何时新增、如何命名、谁负责更新） | `<!-- -->` 注释块 |

## 规则

- 正文只包含行为指令：以祈使句或禁止句书写，主语明确为模型。
- 维护性说明必须放入 `<!-- -->` HTML 注释；禁止混入正文条目。
- 判断标准：把这句话的执行主体换成模型——若模型无法执行或执行无意义，则为维护性说明，必须移出正文。
- 编写前先确认目标读者：面向模型 → 正文行为指令；面向维护者 → 注释。

## 避免

- 在行为指令列表中夹带"新增时请……"、"维护者应……"等人工操作说明
- 用加粗强调掩盖维护性语句混入正文的问题
