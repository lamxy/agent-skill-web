# 工具调用极简规约

适用于主场景已确定后，为补足关键事实、证据或执行必要操作而进行的工具读取、检索、验证、修改或多工具联合处理场景。

规则：
- 本规约不用于决定任务主场景，只在主场景已确定且确需补充证据时按需叠加。
- 先判断当前上下文是否足以稳定回答；若足够，则不调用工具。
- 若仅缺一个关键事实：对话模式下优先追问；自主执行流（子代理、loop、计划执行）中优先用工具补足，追问仅作为工具也无法解决时的兜底。
- 工具调用用于补足关键事实，不用于替代主场景判断、澄清、推理或原始来源验证。
- 工具输入尽量精确、聚焦、最小化。
- 有副作用的工具调用（写文件、发请求、创建/删除资源）须额外确认：操作可逆 → 执行后记录回滚路径；操作不可逆 → 执行前向用户确认。自主执行流中无法确认时，优先跳过或标记 `blocked`，不静默执行不可逆操作。
- 工具输出先压缩、筛选、去重，再写回主会话。
- 不把完整原始输出、长日志、长列表、长 JSON、整份 diff 回灌到主线。
- 多工具结果先去重，再汇总。结果冲突时：标明冲突点与各方证据；有明确可信度差异（原始源 > 摘要，官方 > 第三方）→ 采信高可信度源并说明理由；可信度相当 → 不裁决，呈现冲突并交由用户或主代理决策。
- 主会话只保留结论、关键证据、风险和下一步。
- 工具级联（A 结果触发 B，B 触发 C）默认上限 3 层；达到上限时基于已有结果形成结论，不继续扩张。若确需突破，须有明确理由且每多一层重新评估收益。
- 外部仓库分析默认"轻量探测"优先（README + 顶层目录 + 1 个关键文件）；超出则停止扩张并上报范围与风险。
- 外部网络质量差或首字节缓慢时，降级轻量探测，避免并行扩大外部请求；非阻塞 hook 日志视为噪音，不触发重复调用。
- 工具调用失败（错误、超时、权限不足）时：同类工具可降级 → 切换降级路径，不机械重试原调用；无降级路径 → 基于已有上下文给出带边界的结论，标记证据不足；权限不足 → 上报用户，不静默跳过或扩大范围。同一工具最多重试 1 次，禁止循环重试。
- 若某次外部工具调用已足以形成可用结论，优先带着不完美证据结束，而不是为了完整性继续扩张调用。

## 输出格式
工具结果写回主会话时，必须使用 `expandable/templates/tool-result-summary-template.md` 的 `[tool-summary]` 结构。仅当结果为单一事实且一句话可表达时，允许内联，不强制模板。
