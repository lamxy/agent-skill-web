## 續作時必須知道的事

### 示範資料與完整測試

現象：示範資料存在時，實際啟動 PowerShell 的測試可能在 5 秒門檻逾時。

原因：WSL 的 `pwsh` 冷啟動已接近門檻，示範資料讓共用資料庫查詢再變慢。

正確做法：完整測試使用獨立乾淨的 `TEST_DATABASE_URL`；不要因此修改產品邏輯。清理資料前確認是專用測試庫。

### 分析日期與資料缺口

現象：`toISOString().slice(0, 10)` 在 UTC 跨日會少一天；best-effort 遙測可能出現安裝多於下載。

原因：日期輸入是當地日曆日，查詢契約是 UTC RFC 3339；下載事件可能缺失。

正確做法：預設日期使用 `formatDateInputValue`，由 `buildAnalyticsPath` 轉 UTC 閉區間；資料不一致時呈現 `dataGaps`，不得補值。

### 開發模式的 ERR_ABORTED

現象：Vite dev server 載入任一資料頁時，該頁的 API 請求會出現一次 `net::ERR_ABORTED`。

原因：`web/src/main.tsx` 啟用 React `StrictMode`，開發期 effect 刻意雙掛載；`usePageState` 的 cleanup 正確呼叫 `controller.abort()` 中止第一次請求。

正確做法：這是 `AbortController` 正常運作，不是缺陷，不要為此改產品邏輯。要驗收「無失敗網路請求」時，對 production build（`npm run build` 後 `node dist/server.js`）測，不要對 dev server 測。

### 前端型別

現象：前端不能直接 import 後端型別。

原因：後端用 `NodeNext`，前端用 bundler 解析。

正確做法：後端契約變更時同步 `web/src/api/types.ts`，並以 API 與模型測試固定邊界。

### 9.6 線框與實作邊界

現象：Task 9.6 仍含 Next.js 路徑等過時規劃，且工作台包含列表與詳情兩個視圖。

原因：任務描述早於 Vite/React 決策；專案規則要求單次只探索一個頁面並先審核線框。

正確做法：列表與詳情均已依獨立線框、使用者確認與真實治理 API 完成。後續調整仍以專案文件和實際後端為準。
