# 目錄頁狀態契約

Task #3 只鎖定資料與狀態契約；實際視覺介面由 Task #9 實作。歸檔線框只保留資訊層級，不直接複製粗線框樣式。

## 詳情資料順序

1. 用途、名稱、類型、所有團隊、來源與授權。
2. 版本支援的 Client、Client 版本、適配來源、維護者與作業系統。
3. 發布者在 UI 命令框保存的安裝與解除安裝命令；平台不得硬編碼這一段。
4. 是否有殘留副作用，以及具體殘留內容。
5. 只有 `published` 版本提供下載入口；`review_required` 即使作者或審核人可在詳情看見，也不能下載。
6. 安裝次數、成功次數及成功率；沒有數據時成功率為 `null`，不能顯示虛構的 `0%`。

## 五種頁面狀態

- `loading`：保留頁面結構骨架，不顯示舊套件的安裝命令。
- `empty`：說明目前沒有符合條件的已發布套件，並引導調整篩選或上架套件。
- `error`：顯示可操作原因；`retryable=true` 時提供重新載入。
- `partial`：主資料可用、採用統計等非核心區段失敗時仍允許查看；`unavailableSections` 明確列出缺失區段。
- `success`：核心資料與可用的非核心資料完整。

TypeScript 的唯一來源是 `CatalogPageState<T>`。搜尋 API 直接回傳 `empty` 或 `success`；瀏覽器請求尚未完成、網路錯誤及部分資料退化由 Task #9 的查詢層映射為其餘三態。
