# 第一期發布審核模組實作計畫

> **For agentic workers:** REQUIRED SUB-SKILL: Use `superpowers:executing-plans` to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 建立版本提交驗證、審核決議、重新審核、撤下停用與受影響使用者通知的完整治理閉環。

**Architecture:** 純 TypeScript 狀態機決定合法轉換；`GovernanceService` 負責授權與流程編排；Repository 以 compare-and-set 交易同步寫版本、Review、ValidationRun、通知、Audit 與 Outbox。外部 Runner 位於兩個短交易之間，Linux 使用 Docker，Windows 使用 WSL PowerShell 7，缺少能力不得偽造通過。

**Tech Stack:** Node.js 24、TypeScript 7、Fastify 5、Drizzle ORM、PostgreSQL 17、Vitest、Docker CLI、PowerShell 7。

**Spec:** `docs/superpowers/specs/2026-08-25-第一期發布審核設計.md`

## 全局約束

- 第一期功能閉環優先，只做必要安全與隔離，不提前做第二期全面加固。
- 所有專案文件、測試名稱、使用者訊息與程式註解使用中文；協議欄位與識別字可使用英文。
- 資料模型反範式，禁止外鍵、級聯、SQL `REFERENCES` 與 Drizzle `.references()`。
- 狀態、Review／ValidationRun／通知、Audit、Outbox 必須在同一 PostgreSQL transaction。
- Task #6 不新增 XState 或其他狀態機依賴。
- 不執行 git commit，除非使用者另行明確要求。
