# 第一期身份與權限實作計畫

> **供代理工作者使用：** 必須逐項執行本計畫；本工作階段採 inline execution，依 `superpowers:executing-plans` 執行並以勾選框追蹤。每個程式行為先由失敗測試證明缺口，再做最小實作。

**目標：** 完成 Taskmaster #2 的身份、匿名 UUID、工作階段、疊加角色、審核人管理、作者迴避與稽核 API，同時保留第二期 OIDC provider 接口。

**架構：** 身份提供者只輸出可信身份聲明；身份解析器把不透明 session 或匿名 UUID 解析成聯合型別；授權服務集中處理角色與審核資格；Repository 提供記憶體測試實作與無外鍵 PostgreSQL 實作。Fastify 路由只做輸入驗證、Cookie 傳輸與服務調用。

**技術棧：** Node.js 24、TypeScript 7、Fastify 5、Drizzle ORM 0.45、PostgreSQL 17、Vitest 4、Zod 4。

**規格：** `docs/superpowers/specs/2026-08-25-第一期身份與權限設計.md`

## 全局限制

- 第一期以功能閉環為先，只實作基本安全；真實 OIDC、PKCE、JWKS、MFA、完整 CSRF 與速率限制延至第二期。
- 正式環境未配置正式 provider 時必須 fail closed，不得啟用開發登入。
- 所有資料庫關聯使用邏輯業務 ID；禁止外鍵、`ON DELETE CASCADE` 與 Drizzle `.references()`。
- 身份必須使用 `{ kind: 'authenticated'; uid: ... } | { kind: 'anonymous'; anonymousId: ... }`，匿名 UUID 不得填入 UID。
- 文件、註解與面向使用者文字使用中文；程式識別字、協議與官方名稱除外。
- 使用者未授權建立 Git commit；每個任務以測試綠燈與計畫勾選作為檢查點，不提交工作樹。

- `src/modules/identity/identity-provider.ts`：provider 接口、開發 provider 與正式停用 provider。
- `src/modules/identity/repository.ts`：身份模組資料存取接口。
- `src/modules/identity/memory-identity-repository.ts`：單元及 API 測試使用的確定性 repository。
- `src/modules/identity/postgres-identity-repository.ts`：Drizzle/PostgreSQL 實作與交易稽核。
- `src/modules/identity/session-service.ts`：Token 建立、摘要、解析、撤銷與匿名 UUID。
- `src/modules/identity/authorization-service.ts`：`hasRole`、`canReview` 與審核人指派。
- `src/modules/identity/index.ts`：Fastify plugin factory 與 HTTP 路由。
