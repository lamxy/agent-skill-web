# 第一期遙測上報實作計畫

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 完成公開遙測接收、冪等去重、反範式 PostgreSQL 持久化、晚到事件與 Linux／Windows 斷線補交閉環。

**Architecture:** 復用 `installations` 作唯一不可變事實表，Service 將十一欄 payload canonicalize 後計算 fingerprint，Repository 以 unique idempotency key 做 first-write-wins。腳本在每次實際執行時產生 UUID，先 FIFO 補交舊 queue，再上報本次結果；同步失敗不改寫中部命令退出碼。

**Tech Stack:** TypeScript 7、Fastify 5、Drizzle ORM、PostgreSQL 17、Vitest 4、Bash、PowerShell 7

**Spec:** `docs/superpowers/specs/2026-08-25-第一期遙測上報設計.md`

## Global Constraints

- 所有文件、測試名稱、業務錯誤訊息與新增註解使用中文；識別字、命令與官方名稱可保留英文。
- 資料庫禁止外鍵、cascade、`.references()`；保存 `package_id + version` 快照，數字 ID 只作 legacy 追溯。
- 第一期間不新增 telemetry Audit／Outbox、broker、daemon、簽章或全面安全加固。
- 白名單固定十一欄並包含 `client_runtime`；未知欄位日誌只能保存欄位名稱。
- 同 key 同 canonical payload 成功去重；同 key 不同內容固定回 `409 IDEMPOTENCY_KEY_CONFLICT`。
- 每個實作 Task 完成後獨立提交；Taskmaster 狀態只在專案根目錄更新。

- [ ] **Step 3: 定義 canonical 型別與 fingerprint**

```ts
export interface CanonicalTelemetryEvent {
  idempotencyKey: string;
  packageId: string;
  version: string;
  userRef: string;
  userRefType: 'uid' | 'uuid';
  osType: 'macos' | 'linux' | 'windows' | 'wsl';
  clientRuntime: string;
  status: 'downloaded' | 'succeeded' | 'failed' | 'uninstalled';
  errorCode: InstallErrorCode | null;
  startedAt: Date;
  endedAt: Date;
  payloadFingerprint: string;
  receivedAt: Date;
}
```

fingerprint 只包含 canonical 欄位，按固定 key 順序 JSON stringify 後計算 SHA-256；不得包含 dropped fields 或 receivedAt。

- [ ] **Step 3: 實作可重跑 Migration**

Migration 以 `DO $$`／`information_schema` 安全處理 rename/add/backfill/not-null/index；不得出現 `FOREIGN KEY`、`REFERENCES` 或 cascade。孤兒 placeholder 固定可追溯到 legacy id，fingerprint 使用 `legacy:<installation-id>`。

- [ ] **Step 4: 實作 first-write-wins PG Repository**

先查 `package_versions(package_id, version)` 存在，再：

```sql
INSERT INTO installations (...)
VALUES (...)
ON CONFLICT (idempotency_key) DO NOTHING
RETURNING ...;
```

未返回列時讀既有 fingerprint；相同回 duplicate，不同拋 `IDEMPOTENCY_KEY_CONFLICT`。禁止 `DO UPDATE`。

- [ ] **Step 5: 將採用與通知查詢切到邏輯 ID**

Catalog adoption 按 `installations.package_id = packages.package_id` 聚合；Governance delist/emergency recipients 按 `package_id + version` 查詢，不再依賴 legacy numeric ID。

**Interfaces:**

- Produces: runtime UUID、FIFO pending queue drain、dead-letter、同步中提示。

- [ ] **Step 1: 寫 Linux／PowerShell 失敗測試**

測試同一生成腳本執行兩次產生不同 key；queue retry 保持行內 key；舊三行 FIFO；2xx 移除、5xx 保留當前與後續、永久 4xx 移 dead-letter；同步失敗但安裝成功仍 exit 0 且顯示「安裝成功，資料同步中」。

- [ ] **Step 2: 驗證 RED**

Run: `rtk npm test -- test/script-generator/script-generator-service.test.ts test/governance/validation-runners.test.ts`

Expected: 新增案例 FAIL，因現況 key 固定且 queue 不 drain。

- [ ] **Step 3: 移動 key 到 runtime 並 canonicalize errors**

Linux 使用 `/proc/sys/kernel/random/uuid`，PowerShell 使用 `[Guid]::NewGuid()`；Linux 非零與 PowerShell 未分類錯誤送 `E999`。每個 payload 只含十一欄。

- [ ] **Step 4: 實作 queue lock、FIFO drain 與原子替換**

Linux 使用具名 lock directory、同目錄 temp file 與 `mv`；PowerShell 使用 lock file 的 exclusive `FileStream`、temp file 與 `Move-Item`。補交錯誤只影響 queue，不改寫本次中部命令結果。

- [ ] **Step 5: 更新 validation runner 證據關聯**

Runner 不再從腳本文字提取固定 key；改以執行前 telemetry baseline 與執行後新增 JSON 行驗證 package、version、uid、os、client、status，並要求新增行的 key 是 UUID。install／uninstall 必須各自有新 key，舊 marker 不得冒充。
