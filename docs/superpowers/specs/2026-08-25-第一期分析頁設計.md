# 第一期分析頁設計

## 目標與邊界

Task #8 在既有模組化單體內補全 analytics 模組，讓作者取得可行動的採用分析，讓已登入員工取得自己的安裝與升級狀態。第一期交付 Fastify JSON API，供後續 Web 頁直接消費；不新增前端框架、物化視圖、背景聚合作業或通知派送。

遙測屬 `best-effort`。每份作者分析都明示「數據僅供參考」，不得把缺失事件包裝成完整母體。

## API 與授權

- `GET /api/packages/:packageId/analytics?start=<ISO>&end=<ISO>`：只允許套件作者、owner team 的 `maintainer` 或 `platform_admin`。回傳漏斗、分層成功率、失敗分布、首次可運行時間、活躍版本分布與待升級 UID。
- `GET /api/me/installations`：只允許已登入身份，回傳該 UID 每個套件的當前版本、狀態、推薦版本與是否可升級。
- 匿名請求回 `401`；無權查看作者分析回 `403`；套件不存在回 `404`。所有輸入由 Fastify schema 驗證。

作者分析沿用歸檔 HTML 的閱讀順序：先看三段漏斗與成功率，再看失敗分布及時間，最後看版本與升級行動。API 回應保持同樣區段，避免前端重新猜測資訊層級。

## 指標契約

期間以遙測事件 `startedAt` 落入 `[start, end]` 判定；晚到補交仍歸入實際發生期間，不以接收時間改寫事件語義。

- 漏斗：分別計數 `downloaded`、`succeeded`、`uninstalled` 事件。下載到安裝率為成功數除以下載數；安裝到卸載率為卸載數除以成功數；分母為零時回 `null`。
- 成功率：分母只包含 `succeeded + failed`，回傳成功數、總數、比率與 Wilson 95% 信賴區間。`uid` 與 `uuid` 分開回傳，不產生合併成功率；零樣本的比率與區間為 `null`。
- 失敗分布：同一批 `failed` 事件分別按 version、OS、錯誤碼聚合，並提供 version × OS × errorCode 的 heatmap cells。
- 平台首次可運行時間：每筆成功事件的 `endedAt - startedAt`。員工口徑：同一 package、userRefType、userRef、version 的成功事件，配對不晚於成功的最近下載事件，計算成功結束到下載事件開始時間。因第一期事件沒有共同 attempt correlation，回應明示此口徑為近似值；沒有可配對下載時不虛構樣本。兩者回傳樣本數、中位數、P90、P95；使用 nearest-rank 百分位，無樣本回 `null`。
- 活躍版本：對 package + user 身份按事件時間排序；最近的成功設為當前版本，最近的卸載移除安裝。失敗或下載不改變已安裝狀態。分布按當前版本計數。
- 推薦版本：套件 `published` 版本中最高的有效語意版本。第一期支援 `x.y.z` 與常見 prerelease；無法解析的版本以自然數字段比較作保守後備。
- 待升級使用者：只包含當前版本低於推薦版本、且推薦版支持該使用者最近 OS／Client 的 `uid`。UUID 永不進入通知名單。
- 我的安裝：依相同當前狀態算法，只查登入 UID；每個 package 回傳目前版本、狀態、推薦版本及可升級旗標。

## 模組與資料流

`AnalyticsRepository` 只負責取得遙測事實、套件與版本快照；`AnalyticsService` 負責純統計、狀態折疊、版本比較與授權；Fastify plugin 負責身份解析、輸入驗證與 HTTP 映射。Memory 與 PostgreSQL repository 使用同一契約，避免 API 測試和生產查詢分叉。

PostgreSQL 直接查既有反範式 `installations.package_id + version`，不新增外鍵或跨表約束。新增與實際路徑一致的普通複合索引；資料完整性繼續由遙測 ingest 的版本存在校驗維護。

目前下載 API 不會自行寫入 `downloaded` 事件，只有遙測接收端收到 `downloaded` 才能形成漏斗第一段。分析回應提供 `dataGaps`；期間內沒有下載事件但存在終態時，明示「缺少下載事件」，不把轉化率顯示為 0%。下載事件自動採集屬腳本／下載流程的後續契約，不在分析只讀模組內偷偷補寫。

## 測試與驗收

1. 純服務以手算資料集驗證漏斗、Wilson 95% 區間、兩種百分位、失敗 heatmap、UID／UUID 分層與卸載折疊。
2. API 驗證作者／維護者／管理員授權、匿名與越權拒絕、日期驗證、`best-effort` 標示及我的安裝。
3. PostgreSQL 整合測試驗證期間查詢、使用者查詢、推薦版本與零外鍵。
4. 最終執行定向測試、全量 Vitest、typecheck、build、migration、資料庫健康與外鍵數量查詢。
