# 第一期遙測上報設計

日期：2026-08-25

## 目標

Task #7 建立可直接由安裝腳本呼叫的遙測閉環：嚴格接收固定欄位、以冪等鍵去重、接受斷線後晚到事件、保存反範式套件與版本快照，並讓 Linux／Windows 腳本在下一次執行時依序補交本機佇列。

第一期優先完成功能閉環與基本安全。報告簽章、每套件限流、獨立 telemetry service、外部 message broker、長駐補交 daemon 與全面威脅加固留到第二期。

## 已鎖定決策

### 復用 `installations` 事實表

不新增重複的 `telemetry_events` 表。既有 `installations` 已有使用者參考、OS、Client、狀態、錯誤碼、事件時間與冪等唯一索引；Task #7 將它演進為遙測的唯一不可變事實表。

新增 `package_id`、`version` 與 `payload_fingerprint`。原 `package_version_id` 改名為可空的 `legacy_package_version_id`，只供舊資料追溯；新寫入、通知、採用統計與未來分片都使用文字邏輯 ID，不依賴跨聚合數字 ID。資料庫維持零外鍵、零 cascade、零 `.references()`。

`created_at` 代表服務端接收時間；`started_at`、`ended_at` 代表客戶端事件時間。晚到事件不因時間過舊而拒絕。

### 高併發寫入邊界

遙測本身就是不可變機器事件流，第一期不為每筆事件再複製 Audit 與 Outbox，避免三倍寫入、索引膨脹及未來批量導入瓶頸。治理決策、身份與人工操作仍依既有規則同交易寫 Audit／Outbox；若第二期需要串流消費，再由 telemetry 專用 CDC／Outbox 批次發布。

### 公開接收端點

`POST /api/telemetry/report` 不依賴 Cookie session，因為安裝腳本可能在未登入環境執行。基本安全邊界如下：

- 只接受 JSON object 與明確欄位型別、長度、枚舉及 RFC 3339 時間。
- `idempotency_key` 必須是 UUID。
- `user_ref_type=uuid` 時 `user_ref` 必須是 UUID；UID 只允許有限長度的安全文字。
- 先以 `package_id + version` 做應用層存在性校驗；已撤下版本仍可接受舊腳本的晚到結果。
- 額外欄位會被丟棄；日誌只記錄欄位名稱與 request id，不記錄值、完整 payload、環境變數或命令輸出。
- 首期不宣稱報告來源不可偽造；每腳本簽章與 replay window 留到第二期。

正式白名單共有十一欄：

```text
idempotency_key, package_id, version, user_ref, user_ref_type,
os_type, client_runtime, status, error_code, start_time, end_time
```

`client_runtime` 必須保留，因為 Codex／Claude Code 是鎖定分析維度；Taskmaster 範例漏列此欄，不作為刪除依據。

## 資料契約

```ts
interface TelemetryReport {
  idempotency_key: string;
  package_id: string;
  version: string;
  user_ref: string;
  user_ref_type: 'uid' | 'uuid';
  os_type: 'macos' | 'linux' | 'windows' | 'wsl';
  client_runtime: string;
  status: 'downloaded' | 'succeeded' | 'failed' | 'uninstalled';
  error_code?: 'E001' | 'E002' | 'E003' | 'E004' | 'E005' | 'E006' | 'E999';
  start_time: string;
  end_time: string;
}
```

`end_time` 不得早於 `start_time`。`failed` 必須保存結構化錯誤碼；非失敗狀態一律正規化為 `null`。為兼容 Task #5 已生成腳本，接收端暫時把 `exit_<n>` 與 `powershell_error` 映射為 `E999`，不保存原始命令輸出。新版腳本只發送 canonical error code。

錯誤碼固定為：

| 代碼 | 分類 |
| --- | --- |
| `E001` | 缺少依賴 |
| `E002` | 權限不足 |
| `E003` | 網路不可達 |
| `E004` | 磁碟空間不足 |
| `E005` | 版本衝突 |
| `E006` | 腳本逾時 |
| `E999` | 未分類錯誤 |

## 冪等與並發

每次「實際執行」腳本時產生新 UUID；同一 pending queue 項重試時保持原 key。不能在下載或生成腳本時固定 key，否則同一腳本重跑會被錯誤去重。

服務端對 canonical payload 計算 SHA-256 fingerprint：

- 首次 key：`INSERT ... ON CONFLICT DO NOTHING RETURNING`，回 `201` 與 `duplicate: false`。
- 相同 key、相同 fingerprint：回成功與 `duplicate: true`，不新增資料。
- 相同 key、不同 fingerprint：回 `409 IDEMPOTENCY_KEY_CONFLICT`，不得覆寫第一份結果。
- 兩個並發相同請求最終只能保存一列；衝突後重新讀取既有列判斷相同或不同內容。

## 晚到事件與狀態投影

每筆報告只追加，不修改其他報告。採用統計直接按事實表聚合；若需要同一使用者／套件／OS／Client 的目前狀態，排序鍵固定為：

```text
started_at → ended_at → created_at → id
```

抵達順序不參與業務先後判斷，因此晚到的舊 `succeeded` 不會覆蓋較新的 `uninstalled`。

## 本機斷線補交

Linux 與 Windows 都使用 `~/.agent-platform/pending_reports.jsonl`，每行只保存白名單 payload。每次腳本執行先補交舊項，再執行本次中部命令與上報本次結果：

1. 取得單使用者 queue lock，避免並發腳本同時改寫。
2. 依 JSONL FIFO 發送；2xx 與服務端 duplicate 都視為確認。
3. 網路或 5xx 發生時停止補交，原子保留該行與後續行。
4. 永久 4xx 移到脫敏 dead-letter，避免壞資料永久阻塞 queue。
5. 以同目錄暫存檔加 rename／move 原子替換 queue。
6. queue 補交或當次上報失敗都不得改寫中部命令的原始退出碼。

第一期補交依賴下一次腳本執行，不新增長駐 daemon。安裝命令成功但本次事件入隊時，腳本直接顯示「安裝成功，資料同步中」；解除安裝使用對應文案。這是本機呈現狀態，不新增服務端 installation status。

## 模組邊界

```text
telemetry/index.ts                         Fastify schema、丟棄欄位日誌、HTTP response
telemetry/telemetry-service.ts             canonicalization、時間與錯誤碼規則、fingerprint
telemetry/repository.ts                    不可變 ingest contract
telemetry/memory-telemetry-repository.ts   共用 MemoryPlatformStore、copy-on-write
telemetry/postgres-telemetry-repository.ts INSERT DO NOTHING、並發衝突判斷
script-generator-service.ts                runtime key、FIFO queue drain、同步中提示
```

Memory 與 PostgreSQL 必須共享相同語義。Memory app 仍使用同一 `MemoryPlatformStore`，確保遙測寫入能被治理通知與採用統計看到。

## Migration

新增 `0009_telemetry.sql`，必須同時支援乾淨資料庫、舊資料庫及 raw SQL 重跑：

- 安全改名或新增 `legacy_package_version_id`。
- 新增並回填 `package_id`、`version`、`payload_fingerprint`。
- 舊孤兒資料使用可追溯的 legacy placeholder，不建立外鍵。
- 新增 `(package_id, version, status, started_at)` 與 `(user_ref_type, user_ref, created_at)` 索引。
- 保留 `idempotency_key` 唯一索引。
- 公開 schema 外鍵數量必須保持 0。

## 測試與驗收

- Service：十一欄白名單、額外欄位只記名稱、UUID／時間／狀態／錯誤碼、legacy error 映射、晚到事件。
- Memory repository：首次、相同 duplicate、不同內容 conflict、共用 store 採用可見性。
- PostgreSQL repository：首次、並發 duplicate、conflict、package/version 不存在、migration 回填與重跑、零外鍵。
- API：無 session 可上報、201／200 duplicate／409、OpenAPI、額外欄位警告不含值。
- Script：每次執行新 key、同 queue 項 key 不變、Linux／PowerShell FIFO 補交、部分成功、同步中提示、原退出碼不變。
- 回歸：typecheck、build、全量 Vitest、migration 連續兩次、DB health。
