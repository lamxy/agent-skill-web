### D-4 正式環境首位 platform_admin 無產生路徑（阻塞 SSO 正式上線）

- 提出日期：2026-08-29，於 Task 10.6 繪製 SSO 身份體系線框時發現。
- 現象：授予角色本身需要 `platform_admin`（`AuthorizationService.requirePlatformAdmin`），但正式環境沒有任何管道產生第一個 `platform_admin`。開發環境靠 `createIdentityModule` 中對 `dev-admin` 的硬編碼分支自動授予，該分支只在 `provider.kind === 'development'` 時觸發，改用 OAuth2 provider 後不再生效。
- 後果：即使 SSO 接通、員工能登入，也無人能指派審核人或授予任何角色，審核流程整體無法啟動。這不是 SSO 本身的缺陷，但會在正式上線當天才顯現。
- 候選作法：
  - A：環境變數指定 bootstrap 管理員 uid，啟動時若該 uid 尚無 `platform_admin` 則授予。可審計，但需注意 uid 必須與 IdP 回傳一致。
  - B：一次性 CLI 腳本，由運維在部署後手動執行一次。
  - C：migration 種子資料寫入固定 uid。最簡單，但 uid 需在部署前確定，且不易隨環境變化。
- **2026-08-29 結案：採 A，環境變數指定 uid。** 使用者定案。`BOOTSTRAP_ADMIN_UID` 指定的 uid 登入時，若尚無 `platform_admin` 則自動授予 global 範圍，`assignedByUid` 記為 `bootstrap` 以與人為授予區分，並寫入 warn 層級日誌留痕（只記 uid，不記其他身份欄位）。
  - 選 A 而非 B 或 C 的理由：B 需要生產環境的 shell 存取權，且忘記執行要到上線後才發現；C 把 uid 寫死在 migration，各環境無法給不同 uid，改動還要新 migration。A 冪等、可審計、換管理員只需改環境變數重啟。
  - 刻意的行為：管理員被撤銷後重新登入會再次取得。否則撤銷最後一位管理員會讓平台永久失去授權能力，且無法自救。此行為以測試固定。
  - 未配置時不授予任何人，開發環境的 `dev-admin` 分支維持不變。
  - 驗收：7 項測試涵蓋未配置、正確授予、他人不受影響、重複登入不重複授予、`assignedByUid` 標示，以及取得管理員後可實際指派審核人（證明授權鏈完整）。

### D-5 MVP 階段的部署與演示環境降級

- 提出日期：2026-08-29。
- 背景：Task 10.9 與 10.11 原本假設公司提供 VM Pool 與 Kubernetes 叢集，因此在 D-2 被列為硬阻塞。使用者確認目前為個人開發與 MVP 驗證階段，不需要也不應引入該等基礎設施。
- 決策結果：**降級為單機方案，2026-08-29 定案**。
- 判斷依據：MVP 階段要驗證的是平台功能閉環——上架、審核、腳本生成、下載、遙測回報是否能走通——而不是部署基礎設施的成熟度。以 Kubernetes 驗證單人使用的平台，投入與收益不成比例，且會讓本可推進的工作停在等待外部資源。

| 項目 | 原方案 | MVP 方案 |
|---|---|---|
| 部署形態 | Kubernetes 叢集 | Docker Compose 單機，直接 build 不推 registry |
| 發布策略 | 灰度發布與零停機 | `compose up -d --build` 重建，接受短暫停機 |
| 回滾 | 叢集層回滾 | 切回前一個 image tag 或 git revert 後重建 |
| 監控 | 生產級 APM 與告警 | 結構化日誌加輕量健康輪詢，異常走 Task 10.10 通知渠道 |
| 演示環境 | VM Pool 或 DinD 覆蓋四系統 | 本機 Compose，驗證 Linux/macOS 與 WSL 兩個目標 |

- 明確的能力邊界：Windows 原生與 macOS 原生的腳本執行**未經平台驗證**。這兩個系統的生成腳本仍可下載，但平台端沒有實際跑過。此限制必須在文件標明，不得讓使用者誤以為四個系統都已驗證——這與 P2-3「不用靜態分析推導權限」是同一條原則：不聲稱未經證實的事。
- 升級路徑：Dockerfile 為多階段且已非 root 執行，`/health` 端點與 `HEALTHCHECK` 均已就緒，CI 也已驗證映像可建置。要轉為 Kubernetes 時不需重寫容器化，只需補 manifest 與 registry 推送。降級不製造技術債。
- 不受影響的項目：10.6 SSO 與 10.10 通知渠道的外部依賴性質不變，仍待真實憑證。
