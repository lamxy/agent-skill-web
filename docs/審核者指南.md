# 審核者指南

## 審核順序

1. 確認作者與 owner team 迴避規則已生效。
2. 比對提交快照中的 package、version、命令全文、digest、OS／Client 矩陣與殘留聲明。
3. 檢查四組 Linux／Windows × Codex／Claude Code 的 Runner 結果；任一組缺少證據都不能發布。
4. 比對安裝前後檔案快照，依殘留清單核對解除安裝結果。
5. 只有安裝、遙測、解除安裝、清理全部通過才可核准。

## Runner 證據

Linux 使用固定 Docker image、唯讀輸入 mount、無網路、drop capabilities、資源限制與完成後具名容器清理。Windows 第一期使用 WSL 內 PowerShell 7，注入隔離的 `HOME` 與 `APPDATA`；這能驗證 PowerShell 行為，但不等同原生 Windows Server／Desktop VM。

`telemetryAssurance` 固定為 `best-effort`。父層 EXIT trap、唯讀變數、子程序隔離與命令拒絕規則可擋常見繞過，但同一使用者權限下的惡意命令仍可能竄改本機 capture。第一期證據用於功能驗證，不宣稱不可偽造；獨立權限 capture、隔離 VM、簽章與 attestation 留到第二期。

## 殘留判定

檔案快照只排除平台自己的 queue、dead-letter、lock 與 Runner evidence。套件寫入平台目錄的其他檔案仍算殘留。服務、cron、scheduled task、系統設定與外部資源需依維護者聲明人工核對；第一期沒有宣稱單靠檔案 diff 可覆蓋所有副作用。

macOS 必須顯示 `not_supported`；Runner unavailable、timeout、證據不完整或 adapter 例外都應失敗，不得人工改成 passed。
