# 維護者指南

## 發布前資料

每個版本必須填寫用途、版本說明、支援 OS、支援 Client、安裝命令、解除安裝命令、授權、來源與殘留副作用。第一期可驗證矩陣固定為 Linux／Windows × Codex／Claude Code；不要宣稱 macOS 或原生 Windows VM 已通過。

命令框只負責中部業務命令。不得寫入 `_ASP_` 變數、遙測 endpoint、`trap`、`exec`、`source`、`Remove-Variable`、`Set-Variable` 或其他控制平台頭尾的指令。秘密由目標環境提供，不得硬編碼進命令、輸出或版本說明。

## 安裝與解除安裝

- 安裝命令要可重跑；已存在資源應更新或明確跳過。
- 解除安裝只清理目前套件建立的內容，不刪除使用者共用設定。
- 命令須保留原生退出碼；成功為 `0`，失敗使用非零值。
- Linux 使用 Bash；Windows 使用 PowerShell 7。Windows 不要求終端使用者安裝 WSL，`powershell-wsl` 只表示第一期審核環境。

## 殘留聲明

只要解除安裝後仍保留下列任一項，就必須勾選有殘留並填寫原因與人工清理步驟：

- 新增或修改設定檔。
- 系統設定、環境變數或權限變更。
- 系統服務、背景程序、cron 或 scheduled task。
- 套件快取以外的檔案、資料庫或憑證。

平台產生的 UUID、pending queue、dead-letter 與 lock 是平台基礎設施，不可被維護者命令修改，也不能拿來隱藏套件殘留。

## 提交與修訂

先在預覽確認命令全文、digest、矩陣及殘留聲明，再提交驗證。Runner 失敗時依 `install_failed`、`uninstall_failed`、`telemetry_missing`、`cleanup_failed` 或 `runner_timeout` 修正版本；不要重複提交相同內容規避失敗證據。
